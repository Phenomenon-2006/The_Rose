# Midnight Rose — راهنمای کامل نصب و استقرار

یک فضای خصوصی دو نفره: اتاق گفتگوی اصلی برای دو نفر + یک اتاق آزمایشی کاملاً جدا.
میزبانی: **Vercel** — پایگاه داده: **Supabase** — هیچ اعلان (Notification) و هیچ درخواست دسترسی‌ای وجود ندارد.

---

## ۰) این پروژه دقیقاً چه کاری می‌کند؟

- صفحهٔ ورود فقط یک فیلد رمز و یک دکمه دارد.
- **سه رمز** وجود دارد: رمز نفر اول (A)، رمز نفر دوم (B) و رمز اتاق آزمایشی (TEST).
  - A و B هر دو وارد **یک** اتاق مشترک می‌شوند و پیام‌های هم را می‌بینند.
  - رمز TEST فقط وارد اتاق آزمایشی جدا می‌شود؛ نه پیام اصلی را می‌بیند و نه می‌تواند چیزی بفرستد.
- در صفحهٔ ورود معلوم نیست هر رمز مال کیست.
- پیام‌ها در Supabase ذخیره می‌شوند و بعد از رفرش، بستن مرورگر، خاموش‌شدن گوشی و تعویض دستگاه باقی می‌مانند.
- پیام‌های جدید هر ۳ ثانیه (و وقتی صفحه بسته/پنهان است هر ۱۵ ثانیه) بررسی می‌شوند. (به‌جای Realtime از این روش ساده استفاده شده تا پروژه سبک و قابل انتقال بماند.)

### چرا امن است؟ (خلاصه)
- رمزها هیچ‌جا در کد سایت نیستند؛ فقط **هش** آن‌ها (scrypt) در تنظیمات محرمانهٔ Vercel نگهداری می‌شود.
- بعد از ورود، یک کوکی امضاشده (HttpOnly, Secure, SameSite=Strict) ساخته می‌شود. **سرور** از روی آن تشخیص می‌دهد تو کی هستی و به کدام اتاق دسترسی داری. مرورگر نه فرستندهٔ پیام را تعیین می‌کند و نه شمارهٔ اتاق را.
- دیتابیس: Row Level Security روشن است و **هیچ سیاستی (policy) برای کاربران عمومی تعریف نشده**؛ یعنی با کلید عمومی Supabase هیچ‌کس نمی‌تواند چیزی بخواند یا بنویسد. فقط سرور سایت با کلید محرمانه (service_role) به دیتابیس دسترسی دارد. علاوه بر آن، یک قید (constraint) در خود دیتابیس اجازه نمی‌دهد پیام TEST در اتاق اصلی یا پیام A/B در اتاق آزمایشی ذخیره شود.
- محدودیت تلاش ورود: بعد از ۸ رمز اشتباه از یک شبکه، به مدت ۱۵ دقیقه ورود قفل می‌شود. (حتی رمز درست در این مدت پذیرفته نمی‌شود.)
- متن پیام‌ها همیشه به‌صورت متن ساده نمایش داده می‌شود (نه HTML)، و سربرگ‌های امنیتی (CSP و ...) در `vercel.json` تنظیم شده‌اند.

## ۱) آماده‌سازی روی کامپیوتر

1. **Node.js** (نسخهٔ LTS، حداقل ۱۸) را نصب کن. فقط برای ساخت رمزها و بکاپ لازم است و سنگین نیست.
2. پوشهٔ پروژه را از ZIP بیرون بیاور.
3. (اختیاری) پیش‌نمایش محلی بدون هیچ حساب و دیتابیس:
   ```
   cd midnight-rose
   node tools/dev-server.js
   ```
   سپس `http://localhost:3000` را باز کن. در این حالت یک دیتابیس موقت داخل حافظه استفاده می‌شود (با خاموش‌شدن برنامه پاک می‌شود) و رمزهای نمایشی `rose-a` ، `rose-b` و `rose-test` فعال‌اند. این فقط برای دیدن ظاهر و کارکرد است.

### عکس رز خودت
تصویر پس‌زمینهٔ فعلی یک رز تولیدشده به‌صورت برنامه‌ای است (چون در ساخت پروژه به اینترنت دسترسی نداشتم تا عکس واقعی بگیرم). برای استفاده از عکس واقعی، یک عکس رز قرمز (مربع یا نزدیک به مربع، حدود ۱۴۰۰ پیکسل، حجم زیر ۲۰۰ کیلوبایت) را با نام `rose.jpg` در این مسیر جایگزین کن:
`public/assets/images/rose.jpg`
بهتر است رز در مرکز عکس باشد و حاشیه‌ها تیره باشند. حتماً عکسی را انتخاب کن که حق استفاده‌اش را داری.

### فونت
فونت فارسی پیش‌فرض (DejaVu Sans) داخل پروژه است و از هیچ CDN بارگذاری نمی‌شود. برای ظاهر زیباتر می‌توانی فونت **Vazirmatn** (مجوز آزاد OFL) را خودت دانلود کنی و فایل `Vazirmatn-Regular.woff2` را در `public/assets/fonts/` بگذاری، سپس در `public/assets/css/style.css` علامت‌های کامنت دور بلوک `@font-face` مربوط به Vazirmatn را بردار.

## ۲) ساخت رمزها (روش امن راه‌اندازی)

در پوشهٔ پروژه اجرا کن:
```
node tools/setup-secrets.js
```
برنامه نام نمایشی دو نفر و سه رمز را می‌پرسد (هنگام تایپ رمز، ستاره نمایش داده می‌شود) و در پایان این خطوط را چاپ می‌کند:
```
SESSION_SECRET=...
PASSWORD_HASH_A=...
PASSWORD_HASH_B=...
PASSWORD_HASH_TEST=...
NAME_A=...
NAME_B=...
```
این خروجی را برای مرحلهٔ ۶ نگه دار. خود رمزها هیچ‌جا ذخیره نمی‌شوند. سه رمز باید متفاوت باشند و حداقل ۶ کاراکتر.

**تغییر رمز در آینده:** دوباره همین دستور را اجرا کن و مقدارهای جدید را در Vercel جایگزین کن و دوباره Deploy بزن.
**خارج‌کردن همهٔ دستگاه‌ها:** فقط `SESSION_SECRET` را عوض کن.

---

## ۳) ساخت حساب‌ها

1. **GitHub**: حساب بساز (برای اتصال به Vercel لازم است).
2. **Vercel**: به vercel.com برو و با GitHub ثبت‌نام کن (طرح Hobby رایگان).
3. **Supabase**: به supabase.com برو و ثبت‌نام کن (طرح Free).

> دسترسی به این سرویس‌ها از ایران ممکن است بدون VPN مشکل داشته باشد. این موضوع به محدودیت‌های شبکه بستگی دارد و من نمی‌توانم وضعیتش را تضمین کنم.

---

## ۴) ساخت پروژهٔ Supabase و دیتابیس

1. در Supabase روی **New project** بزن. یک نام (مثلاً midnight-rose)، یک رمز قوی برای دیتابیس (آن را ذخیره کن) و نزدیک‌ترین Region را انتخاب کن.
2. صبر کن پروژه آماده شود.
3. از منوی چپ **SQL Editor ← New query** را باز کن.
4. کل محتوای فایل `database/schema.sql` را کپی و Paste کن و **Run** بزن. باید پیام موفقیت ببینی.
5. در **Table Editor** باید سه جدول ببینی: `rooms`، `messages`، `login_attempts`. کنار هر کدام نشان RLS فعال است.

### گرفتن آدرس و کلید
در **Project Settings ← API** (یا بخش API Keys):
- `Project URL` را کپی کن؛ این مقدار `SUPABASE_URL` است.
- کلید **محرمانه** (در رابط‌های جدید `secret key` و در رابط قدیمی `service_role`) را کپی کن؛ این مقدار `SUPABASE_SERVICE_ROLE_KEY` است.

⚠️ این کلید دسترسی کامل دارد. هرگز در GitHub، چت یا فایل‌های سایت نگذارش. کلید `anon / publishable` در این پروژه اصلاً استفاده نمی‌شود.
(اسم‌ها و جای منوها در Supabase ممکن است عوض شده باشد؛ اگر دقیقاً مثل بالا نبود، دنبال همین دو مقدار بگرد.)

---

## ۵) گذاشتن پروژه در GitHub

1. در GitHub یک مخزن (repository) **خصوصی** جدید بساز.
2. محتوای پوشهٔ `midnight-rose` را در آن آپلود کن (در GitHub گزینهٔ *Add file ← Upload files* کافی است).
3. مطمئن شو فایل `.env` یا هر فایلی که کلید واقعی دارد آپلود نشود (در `.gitignore` مسدود شده است). فقط `.env.example` که مقدار ساختگی دارد آپلود می‌شود.

---

## ۶) اتصال به Vercel و تنظیم متغیرها

1. در Vercel: **Add New ← Project** و مخزن را انتخاب کن (Import).
2. Framework Preset را روی **Other** بگذار. Build Command و Output Directory را دست نزن (تنظیمات در `vercel.json` است).
3. قبل از Deploy بخش **Environment Variables** را باز کن و این هشت مقدار را اضافه کن:

| نام | مقدار |
|---|---|
| `SUPABASE_URL` | آدرس پروژهٔ Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | کلید محرمانه |
| `SESSION_SECRET` | از خروجی مرحلهٔ ۲ |
| `PASSWORD_HASH_A` | از خروجی مرحلهٔ ۲ |
| `PASSWORD_HASH_B` | از خروجی مرحلهٔ ۲ |
| `PASSWORD_HASH_TEST` | از خروجی مرحلهٔ ۲ |
| `NAME_A` | نام نمایشی نفر اول |
| `NAME_B` | نام نمایشی نفر دوم |

4. **Deploy** را بزن. بعد از چند دقیقه یک آدرس مثل `https://midnight-rose-xxxx.vercel.app` می‌گیری.
5. اگر بعداً متغیری را تغییر دادی، باید دوباره Deploy (Redeploy) کنی.

---

## ۷) تست

### تست با دو گوشی
1. روی گوشی اول آدرس را باز کن و رمز A را بزن.
2. روی گوشی دوم (یا یک مرورگر دیگر) رمز B را بزن.
3. از هر طرف پیام بفرست. باید ظرف چند ثانیه روی گوشی دیگر ظاهر شود.
4. صفحه را ببند و دوباره باز کن؛ اگر کوکی هنوز معتبر باشد مستقیم وارد می‌شوی (۳۰ روز) و پیام‌ها همان‌جا هستند.

### تست اتاق آزمایشی
1. با رمز TEST وارد شو؛ نشان کوچک `TEST ROOM` را می‌بینی و اتاق خالی است.
2. چند پیام بفرست. این پیام‌ها در اتاق اصلی نمایش داده نمی‌شوند و پیام‌های اتاق اصلی هم اینجا نیستند.

### چیزهایی که باید نمایش داده **نشود**
هیچ پنجرهٔ اجازهٔ اعلان، دوربین، میکروفون یا موقعیت مکانی. (مرورگر ممکن است خودش پیشنهاد ذخیرهٔ رمز بدهد؛ این به سایت ربطی ندارد و می‌توان رد کرد.)

## ۸) بکاپ دستی و بازیابی

بکاپ فقط از **کامپیوتر خودت** و با کلید محرمانه انجام می‌شود؛ هیچ آدرس مدیریتی روی سایت وجود ندارد.

### گرفتن بکاپ
1. فایل `.env.example` را کپی کن و اسمش را `.env` بگذار.
2. فقط دو خط اول را با مقدار واقعی پر کن (`SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY`).
3. اجرا کن:
   ```
   node tools/backup.js
   ```
4. در پوشهٔ `backups/` این فایل‌ها ساخته می‌شود:
   - `midnight-rose-تاریخ.json` — همهٔ پیام‌ها (برای بازیابی)
   - `...-main.txt` و `...-test.txt` — متن خوانا برای هر اتاق
5. این فایل‌ها را در چند جا نگه دار (فلش، هارد، یک ایمیل رمزگذاری‌شده). پوشهٔ `backups` در `.gitignore` است و نباید در GitHub قرار بگیرد.

نکته: Supabase طرح رایگان بکاپ قابل دانلودی برای تو تضمین نمی‌کند؛ پس بکاپ دستی همین روش است. از **Table Editor ← Export** هم می‌توانی خروجی CSV بگیری.

### بازیابی پیام‌ها
1. جدول‌ها را با `schema.sql` بساز (اگر دیتابیس جدید است).
2. اجرا کن:
   ```
   node tools/restore.js backups/midnight-rose-تاریخ.json
   ```
3. اگر دیتابیس از قبل پیام داشته باشد، برنامه برای جلوگیری از تکرار هیچ کاری نمی‌کند. فقط اگر مطمئنی گزینهٔ `--append` را اضافه کن.

## ۹) محدودیت‌های طرح رایگان (بررسی کن، ممکن است عوض شده باشند)

- **Supabase Free**: پروژه‌هایی که مدتی (در زمان نگارش، حدود یک هفته) فعالیت ندارند ممکن است موقتاً Pause شوند و باید دستی از داشبورد دوباره فعال شوند. سقف حجم دیتابیس هم محدود است (در زمان نگارش حدود ۵۰۰ مگابایت) که برای پیام‌های متنی بسیار زیاد است.
- **Vercel Hobby**: برای استفادهٔ شخصی و غیرتجاری است و سقف مصرف دارد؛ برای یک چت دو نفره معمولاً کافی است. پیام‌خوانی هر ۳ ثانیه تعداد درخواست دارد؛ اگر سقف مصرف دیده شد، فاصله را در `public/assets/js/app.js` (عدد `3000`) بیشتر کن.
- بعد از Pause شدن Supabase سایت پیغام «ارسال نشد» یا «بارگذاری نشد» نشان می‌دهد تا پروژه دوباره فعال شود.

## ۱۰) قطع اینترنت بین‌الملل در ایران

- Vercel و Supabase سرویس‌های خارجی هستند. در زمان اختلال یا قطع اینترنت بین‌الملل ممکن است سایت یا دیتابیس از داخل ایران در دسترس **نباشد**.
- اینکه سایت روی Vercel است به معنی دسترسی از شبکهٔ ملی اطلاعات نیست و هیچ تضمینی برای دسترسی‌پذیری در زمان قطعی داده نمی‌شود.
- هم سایت و هم دیتابیس باید در دسترس باشند.

### آمادگی برای انتقال به هاست ایرانی
- فرانت‌اند فقط HTML/CSS/JS ساده است و به هیچ CDN یا سرویس خارجی وابسته نیست.
- دیتابیس یک PostgreSQL معمولی است (`database/schema.sql`).
- منطق سرور در پوشهٔ `api/` و `lib/` با Node.js ساده و بدون پکیج نوشته شده است. فقط فایل `lib/db.js` با Supabase صحبت می‌کند؛ برای انتقال کافی است همین فایل را با یک اتصال مستقیم PostgreSQL (مثلاً پکیج `pg`) عوض کنی. فایل‌های `tools/dev-server.js` نشان می‌دهد چطور می‌توان همین APIها را بدون Vercel اجرا کرد.
- بکاپ دستی را مرتب بگیر تا انتقال آسان باشد.

```
├── .env.example            ← نمونه تنظیمات (فقط مقدار ساختگی)

└── README-FA.md
```

## ۱۲) عیب‌یابی

- **«مشکلی پیش آمد» هنگام ورود**: معمولاً یکی از متغیرها در Vercel ناقص است یا بعد از تغییر Redeploy نشده. در Vercel بخش *Logs* پیام خطا را نشان می‌دهد.
- **رمز درست را قبول نمی‌کند**: ممکن است ۸ تلاش ناموفق انجام شده و ۱۵ دقیقه قفل باشد. یا هش را ناقص کپی کرده‌ای (باید با `s1:` شروع شود).
- **پیام‌ها نمی‌آیند**: مطمئن شو `schema.sql` کامل اجرا شده و `SUPABASE_URL` بدون `/` اضافه است.
- **هر دو نفر پیام‌های هم را نمی‌بینند**: رمز A و B باید با دو هش جدا ساخته شده باشند و هر دو در اتاق اصلی‌اند؛ اگر یکی TEST را زده، در اتاق آزمایشی است.

## ۱۳) آنچه تست شده و آنچه نه

**تست‌شده (روی کامپیوتر، با دیتابیس ساختگی در حافظه و مرورگر واقعی):** ورود سه رمز، جداسازی اتاق‌ها، رد شدن رمز اشتباه و کوکی جعلی، قفل شدن بعد از ۸ تلاش، رد درخواست از سایت دیگر، پیام‌رسانی بین دو نشست جدا، نمایش فارسی/انگلیسی، بکاپ و بازیابی.
**تست‌نشده:** اجرا روی Vercel و Supabase واقعی (حساب این‌ها در دسترس من نبود). اولین بار که مراحل ۴ تا ۷ را انجام می‌دهی همان تست اصلی است. اگر خطایی دیدی، متن خطا را برایم بفرست تا اصلاحش کنم.
